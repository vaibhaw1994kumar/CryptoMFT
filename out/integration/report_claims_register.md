# Report claims register

Built 5 Nov 2026 from 14 reports. Purpose: nothing a report says we built may be lost when backtest and core become one platform. Companion to `single_platform_plan.md`; requirement checklist in `requirements_checklist.md`.

## How this was checked

- 7 reports read by an extraction pass, 7 by hand; 315 claims in total. 29 manual rows are the `M` ids.
- Each claim's code names were searched in `src/crypto_stat_arb/*.py`, `src/new_backtest/`, `profiles/perp_perp_maker_taker_v1_1.yaml`, then tests, scripts, `order_lifecycle_logger/` and `out/queue_v2/`.
- A name found means the name exists. It does not prove the behaviour works, and nothing was run. Behaviour proof comes from Step 1 scenarios and parity.
- Destination is a first pass by rule. REVIEW means the row is a test, study, process or decision with no code destination, or needs a person. Gate 1 confirms it.
