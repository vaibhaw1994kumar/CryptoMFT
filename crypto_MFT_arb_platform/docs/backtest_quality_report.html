PRESENT

Forward Bias

The FillModelV2 was calibrated on the same 2022-01-13 data the backtest consumed. Because fill_model_v1_path=None, the model was never loaded during the run — so it did not bias trade decisions. However, the calibration output cannot be trusted for forward use without a temporal split.

The leakage guard in backtester.py:226 raises ValueError if trained_until_ts > start_epoch, but it was never triggered because trained_until_ts=0.0 — the model was fit without setting the cutoff timestamp.

Walk-Forward Calibration

batch_backtest.run_pair() has a complete walk-forward loop: cold pass → per-fold FillModelV2.fit() with until_ts leakage guard → eval pass with model loaded. Fold boundaries are calendar-day-aligned.

This run called _run_once(cfg) directly, bypassing the fold loop entirely. The parameter wf_window_days=0 is the default and must be explicitly set.

# Activate walk-forward:
from new_backtest.batch_backtest import run_pair

results = run_pair(
    pair="SOLUSDT",
    start_date="2022-01-06",
    end_date="2022-02-06",
    wf_window_days=7,       # 7-day cal window
    wf_step_days=1,         # step 1 day
    min_fill_prob=0.5,      # enable fill gate
    max_adverse_prob=0.15,  # enable adverse gate
)

Fill Prediction Gate

FillModelV2 was calibrated post-hoc but was never loaded during the run. With min_fill_prob=0.0, every signal was sent regardless of predicted fill probability. This means phantom-edge signals — orders with very low actual fill probability — are counted at full edge value.

The model's mean p_fill(5s)=0.945 is suspiciously high because the queue model placed 89% of orders at queue-ahead=0 (see below). This inflates apparent calibration confidence.

Expected Fill Qty (fill_ratio)

Every one of the 443 completed orders has fill_ratio=1.000 and terminal_reason=full_fill. No partial fills, no cancels. This is unrealistically optimistic.

The proximate cause is the queue model: 395 of 443 orders (89.2%) have queue_ahead=0, placing them at the front of the maker queue. The EmpiricalFillModel likely defaults to queue position 0 when it has no prior fill-log evidence (cold start). The remaining 48 non-zero orders have a mean queue of 187.78 — another unrealistically bimodal distribution.

Time to Fill (TTF)

FillModelV2 computes E[TTF] via trapezoidal integration of the survival function over calibrated horizons (1 s / 5 s / 15 s). The sample prediction gives E[TTF]=1.61 s — but this is computed from fill events that all have queue_ahead=0, so the estimate is optimistically biased.

TTF is not currently used as a signal gate. A gate like "skip if E[TTF] > 8 s" would reduce inventory lock-up on slow markets and improve responsiveness to regime changes.

Adverse Selection Gate

Both adverse-selection controls were disabled for this run. The real-time toxic-flow detector (block_on_toxic) was set to False. The model-based adverse gate had max_adverse_prob=1.0, which passes every order regardless of predicted adversity.

The adverse model was calibrated post-hoc with a base rate of 2.3% at h=5 (10/443 orders where price_moved_through=True). The sample prediction yields p_adverse=0.149, which is 6× the base rate — implying the model already identifies high-risk orders. Wiring max_adverse_prob=0.15 would have blocked ~10–15% of fills.

Walk-Forward Retraining

Both the WalkForwardCalibrator class (fill_label.py) and the fold loop in batch_backtest.run_pair() are fully implemented and tested. Neither is activated for multi-day runs.

Recommended cadence for a liquid pair: daily retraining with a 7-day rolling calibration window. Weekly retraining is acceptable for regime-stable periods but risks missing intraday volatility clusters. A single static model trained on one day — as this run produced — will not generalize across market regimes.

Action Plan — Priority Order
1
Fix trained_until_ts in FillModelV2.fit()
Pass trained_until_ts=until_ts when calling FillModelV2.fit(cal_records, ...) inside the walk-forward fold. Currently defaults to 0.0 (epoch 0), which bypasses the leakage guard in backtester.py:226. Without this fix, a future-trained model silently passes the guard.
2
Investigate queue_ahead=0 rate in EmpiricalFillModel
89.2% of orders placing at queue-ahead=0 is the single largest source of result inflation. Audit the cold-start behavior: does it default to position 0 when no prior fill log is available? A conservative default (e.g., queue_ahead = book_depth × 0.1) or a warm start from the prior day's fill log would produce more realistic fills.
3
Switch to run_pair() with wf_window_days=7 for multi-day runs
Replace direct _run_once(cfg) calls with the walk-forward loop. This eliminates forward bias, fits the model before each eval fold, and produces fold-by-fold PnL statistics that can be compared across regimes. The infrastructure is already tested and merged.
4
Enable gates: min_fill_prob=0.5, max_adverse_prob=0.15, block_on_toxic=True
Set these in ArbConfig. Start with conservative thresholds. The toxic-flow block (block_on_toxic=True) requires no model and should be enabled even before the model-based gates are calibrated. Expect signal count to drop by ~20–40% once gates are active; evaluate whether edge per-signal improves enough to compensate.
5
Fix fee preset mismatch (spot vs perp)
The Bybit leg used bybit_spot_mm while Binance used binance_perp_vip0. Use matching product types. For a perpetual-vs-perpetual cross-venue strategy, both venues should use their respective perp fee schedules. This affects the net edge calculation and signal filter threshold.
6
Re-run on 4–8 weeks of data with all fixes applied
The single-day result ($6.01 PnL, 92.1% edge capture) is statistically meaningless as a sizing input. Run run_pair() on a multi-week window with walk-forward active, gates wired, and the queue model fixed. Compare fold-by-fold Sharpe, fill rate, and adversity rate. Only then are the numbers reliable enough for position-limit decisions.
