# Cross-venue alignment

## Immutable stream merge

`CrossVenueStreamMerger` performs a stable k-way merge using the published recorded-time ordering rule. It yields the original frozen `MarketEvent` objects and verifies that every event belongs to its declared input stream. Venue payloads under `native` are neither combined nor overwritten. The alignment report records a hash for every native state so mutation is detectable.

## Shared eligibility rule

`CrossVenueEligibilityPolicy` requires every configured venue book for the canonical instrument. Each input must:

- exist;
- be in `VALID` state;
- have a local receive timestamp;
- not be future-dated relative to evaluation time;
- be no older than `max_book_age_ns`.

Each decision records the venue, book state, last event ID, receive time, age, validity and reason. The decision fingerprint covers the rule version, required venues, instrument, age limit, evaluation time and all input states.

The spread strategy uses this policy before creating an opportunity. The OMS uses the same policy immediately before dispatch and additionally requires the current buy/sell event IDs and fingerprint to match the opportunity. A changed, stale or invalid market state produces a `ROUTE_ELIGIBILITY` rejection before risk reservation or child dispatch.

## Pipeline artifacts

`align-streams` writes three artifacts:

- merged canonical JSONL in deterministic order;
- `.eligibility.jsonl` with a decision after every input event;
- `.alignment.json` with source/output checksums, native-state hashes, ordering rule, eligible/blocked counts and deterministic alignment hash.

The included `data/evidence/alignment/` session can be regenerated byte-identically from the same two venue inputs. The subsequent backtest records the same source-event lineage through opportunity, route eligibility, child orders and PnL.
